# 실제로 겪은 삽질과 거기서 나온 규칙

여러 에이전트를 무인으로 돌려 실제 서비스를 만들면서 **실제로 일어난** 일만 모았다. 서비스 이름·내부 사정은
지우고 모양만 남겼다. 각 항목은 증상 → 원인 → 규칙 → 어디에 반영됐나 순서다.
표기: **[실측]** 로그·CI·재현으로 확인 / **[문서]** 공식 문서로 확인 / **[일반]** 플랫폼의 알려진 동작(이 템플릿에서 재현하지 않음).

읽는 사람: 지휘자(오케스트레이터)와 템플릿을 고치는 사람. 작업 에이전트는 읽지 않아도 된다 — 필요한 규칙은
이미 규약·브리프·스크립트에 들어 있다.

---

## A. 비용(토큰)과 기다림

1. **캐시가 식은 뒤의 요청이 가장 비쌌다** [실측]
   서브에이전트의 프롬프트 캐시는 5분 TTL 이다. 5~60분 쉬었다 다시 부른 요청 251개가 서브에이전트 캐시 쓰기의
   61%를 만들었다(요청당 평균 34만 토큰을 다시 씀). 원인은 긴 테스트·변이 실행 대기, 폴링 루프, 끝난 에이전트 다시 깨우기.
   → **한 번에 5분 넘게 기다리지 않는다.** 로컬 테스트는 바뀐 범위만, 변이 하나에 테스트 스크립트 하나. (L3 「비용 구조」, 브리프 검증 절)

2. **끝난 큰 에이전트를 다시 깨우면 컨텍스트 전체를 다시 쓴다** [실측]
   메시지로 다시 깨운 44회가 큰 캐시 쓰기의 한 덩어리였다. 새로 띄우면 브리프 몇천 + 다시 읽기 수만 토큰이면 된다.
   → 5분 넘게 지났고 컨텍스트 15만 이상이면 **보고서 요약을 붙인 새 브리프**로. (브리프 체크리스트)

3. **큰 컨텍스트 에이전트 16%가 캐시 읽기의 51%** [실측]
   최대 컨텍스트 40만 이상인 에이전트 31개가 요청마다 평균 34만 토큰을 다시 읽었다. 같은 종류의 일이 초기에는
   요청 30~65 수준이었다. 컨텍스트를 채운 것은 파일 읽기(약 62%)와 테스트 출력(약 14%).
   → 작업 묶음은 **컨텍스트 약 25만 안에서** 끝날 크기로. 「이미 확인한 위치」 표를 브리프에 넘기고(탐색은 싼 모델 한 번),
   테스트 출력은 파일로. (브리프, `ops-explorer`, `run-quiet.sh`)

4. **자동 주입되는 지침을 다시 읽고, 지휘자 전용 문서를 모두가 읽었다** [실측]
   루트 CLAUDE.md 는 모든 서브에이전트에 자동 주입되는데 에이전트 49개가 다시 읽었다. 규약 문서는 절반 넘게가
   지휘자 전용(L3)인데 브리프가 「먼저 읽으라」 고 해서 구현자·검증자도 통째로 읽었다(86개 에이전트, 73회 통째 cat).
   → CLAUDE.md 다시 읽기 금지(브리프), 규약을 **L1·L2(모두)** 와 **L3(지휘자 — 자동 호출 꺼진 skill)** 로 분리,
   pre/postflight 는 **실행만**(근거 주석이 길다). [문서] 서브에이전트도 CLAUDE.md 계층을 전부 로드한다(Explore·Plan·`omitClaudeMd` 제외).

5. **보고서를 통째로 읽었다** [실측]
   보고서 중앙값이 1만 토큰대였고 서브에이전트·지휘자가 수백 번 읽었다. 길어진 이유는 「출력 원문을 붙이라」 는 템플릿.
   → 보고서 맨 앞 **`## 요약` 20줄 이내**(postflight 가 검사), 출력 원문 대신 로그 경로. (보고서 템플릿)

6. **지휘 세션 하나를 수주 이어 갔다** [실측]
   요청당 평균 41만 토큰을 다시 읽었고 압축이 20번 일어났다. 1시간 넘게 쉬었다 재개한 요청이 지휘자 캐시 쓰기의 72%.
   → 마일스톤마다 세션을 바꾸고 인수인계는 보고서·이슈 결정 기록에. (L3 「비용 구조」)

7. **토큰 계측 도구가 2배로 셌다** [실측]
   Claude Code 로그는 응답 하나를 내용 블록마다 여러 줄로 쓰고 같은 message.id·같은 usage 를 반복한다. 줄마다 더한
   도구가 캐시 쓰기를 1.96배, 출력을 1.36배로 셌다 — 예산 판단이 2배 비관적이었다. 비용의 큰 몫인 캐시 읽기는 빼고 보여 줬다.
   → message.id 하나를 요청 하나로, 캐시 쓰기 5분/1시간 구분, 단가 비율로 묶은 「입력환산」 열. (`tokens.py`)

## B. 테스트와 CI

8. **릴리즈 시간의 90%가 이미 통과한 테스트를 다시 돌리는 데 쓰였다** [실측]
   PR 에서 24분 돈 스위트를 머지 뒤 main · 릴리즈에서 또 돌렸다.
   → **내용 지문**(추적 파일 blob 해시 목록)을 키로 「통과 기록」 아티팩트를 남기고 같은 내용이면 건너뛴다.
   실측: PR CI 24.6분 → 같은 내용의 main push 0.1분. (`ci/`)
   함정: 문서를 지문에서 빼면 **테스트가 실제로 읽는 문서**가 바뀌어도 다시 돌지 않는다 → 그 파일만 되살린다.
   한계: 지문은 러너 이미지·외부 다운로드 변화를 모른다.

9. **바뀐 범위 선택이 이름 추정이라 과소·과대로 골랐다** [실측]
   핵심 파일 하나를 바꾸면 21개(사실상 전체)를 고르고, 스타일시트를 바꾸면 레이아웃 테스트를 못 골랐다.
   파일 이름 부분 일치로 무관한 테스트가 늘 끼었다.
   → **명시적 매핑 표**(바뀐 파일 → 돌릴 테스트)를 우선하고 추정은 보조로. 거의 모든 e2e 가 타는 파일은 배선 사고를
   잡는 대표 둘만 로컬에서, 전체는 PR CI 가. 최종 관문은 PR CI — 표가 낡으면 늦게 발견될 뿐 출시되지는 않는다.

10. **같은 PR 에 다시 푸시해도 이전 25분 실행이 계속 돌았다** [실측] → `concurrency` 로 PR 만 취소(main · 릴리즈는 취소 금지).

11. **`&&` 사슬이라 앞이 실패하면 뒤가 안 돌고, 어디가 느린지 매번 로그를 뒤졌다** [실측]
    → 묶음(샤드) 러너: 실패해도 끝까지, 스크립트별 시간 표, 설정에 없는 새 테스트는 자동 배정(조용히 빠지지 않게). (`ci/run-shards.js`)

12. **고정 sleep 이 실행 시간의 40% 이상** [실측] — 조건 대기로 바꾸되 「일정 시간 동안 일어나지 않음」 을 보는 검사만 고정 대기를 남긴다.

13. **구조적으로 같은 결과를 10개 해상도로 매번 돌렸다** [실측] — 10개 결과가 완전히 같았다. 대표 몇 개만 기본으로,
    전부는 환경 변수로(엔진 업그레이드 때).

14. **파이프가 실패를 초록으로 만들었다** [일반·문서]
    `명령 | grep … | head` 의 종료 코드는 마지막 명령의 것이다. 공식 문서의 「조용한 테스트」 예시도 이 모양이다.
    → `run-quiet.sh`: 출력은 파일로, 명령 자신의 종료 코드를 그대로. (`grep -q` 는 pipefail 아래에서 SIGPIPE 로 정상 커밋을
    「트레일러 없음」 으로 떨어뜨렸다 — 8KB 커밋 60회 중 2회 [실측]. 출력을 버리는 쪽으로.)

15. **`tail -6` 으로 본 실패 한 번을 끝내 특정하지 못했다** [실측] — 19회 다시 돌려도 재현되지 않았다.
    → 「자르지 않는다」 = **전체를 파일로 보존**하고 실패 블록 전체를 읽는다(컨텍스트에 전부 넣으라는 뜻이 아니다).

16. **두 에이전트가 같은 경로에 e2e 로그를 써서 결과가 섞였다** [실측]
    → 로그·임시 파일은 에이전트·실행마다 고유 경로(`run-quiet.sh` 기본값은 mktemp, `--log` 로 남의 파일을 덮지 않음).

17. **가상 화면의 화면비가 실제와 달라 넘침 검사가 303px 를 놓쳤다** [실측]
    xvfb 기본 1280x1024 는 16:9 가 아니다. 실제 픽셀로 잰 검사는 그 환경에서 실패할 수 없었다.
    → 환경 값을 출력에 찍고, 환경에 의존하지 않는 좌표(디자인 좌표)로 환산해 판정. (L3-11)

18. **테스트는 통과하는데 배선이 끊겨 있었다** [실측] — 표시 계산 함수를 손으로 만든 입력으로 직접 불렀다. 실제 공개 경로를
    타는 시험으로 바꾸고서야 잡혔다. 핵심 배선 한 줄을 지우는 변이를 단위 테스트는 전부 통과했고 e2e 만 잡았다.
    → L2-2(실제 경로 최소 하나), L3-9(변이로 확인).

## C. 게이트(검사 스크립트) 자체의 결함

19. **mawk 에서 `{2,3}` 이 글자 그대로라 L2 게이트가 상시 통과였다** [실측] → 교대(`|`)로. 판정 로직을 일부러 깨진 입력으로 돌려 본다.
20. **주석을 sed 범위로 지운 전처리가 파일을 통째로 잘랐다** [실측] — 주석 문법을 본문에서 언급한 보고서에서. 그 결함을 드러낸 입력이
    그 수정을 설명하는 보고서 자신이었다 → awk 한 번 안에서 섹션 단위, 1열 주석만 주석으로.
21. **환경변수 한 줄로 검사가 꺼졌다** [실측] — 정규식 재정의를 환경변수로 받으면 `RE=.` 로 끝. → 재정의는 커밋되는 설정 파일에서만,
    `unset` 대신 대입(환경으로 넘어온 셸 함수가 `unset` 을 가로챌 수 있다), `GIT_NO_REPLACE_OBJECTS=1`(로컬 replace 로 메시지 바꿔치기 차단).
22. **복사하라고 출력한 블록에 지어낸 줄이 섞였다** [실측] — 줄바꿈이 섞인 값을 한 줄 정규식이 첫 줄만 보고 통과시켰다. → 한 줄 검사·역슬래시 거부.
23. **기준점을 선언으로 바꿀 수 있게 하자 우회가 열렸다** [실측] — `BASE_REF=HEAD~3` 으로 검사 대상이 13→5개. 오탐 원인은 기준점이 아니라
    머지 커밋(→ patch-id 로 건별 면제)과 두 점 diff(→ 세 점). 면제는 범위가 아니라 **항목 이름 + 보고서 기재**로.
24. **얕은 클론에서 `fetch origin <브랜치>` 만 하면 원격추적 ref 가 낡은 채** [실측] — 「최신 기반」 이라는 거짓 답. 전체 refspec 으로.
25. **공동 작성자 줄을 한 문자열로 고정했더니 사실과 다른 기록을 만들었다** [실측] — 모델을 바꾼 뒤에도 옛 이름을 복사했고,
    바로잡으려 하면 검사가 막았다. → 모양으로 검사하고 값은 지휘자가 작업마다 넘긴다.
26. **게이트가 막아야 할 것과 함께 정상 경로를 막았다** [실측] — 더미 키 검사가 무료판 배포까지 막았고, 그 빌드를 검증 명령에
    넣었으면 모든 에이전트가 막혔을 것이다. → L2-4: 무엇이 계속 가능해야 하는지 적고 실제로 돌려 본다.

## D. 저장소·작업 공간

27. **다른 worktree 가 같은 브랜치를 `checkout -B` 로 옮겨 메인 worktree 인덱스가 어긋났다** [실측]
    → 에이전트 브랜치는 **새 이름**. 지휘자가 체크아웃해 둔 브랜치 이름을 쓰지 않는다. (브리프, preflight 안내)
28. **낡은 기준점의 브랜치를 머지하면 남의 작업이 통째로 되돌아간다** [실측 — 직전에 막음] → preflight 기준점 검사 + 머지 직전 재확인(L3-7).
29. **복사본으로 둔 규약이 표류했고 diff 잡음에 숨었다** [실측] — 이식 중 사례 두 줄이 사라졌고, 다른 쪽엔 세 절 중복·한 절 누락.
    → 정본 한 곳(이 템플릿) + 소비자는 lock 으로 고정 + check 가 실패. (`claude-ops`)
30. **4.5MB 한 줄짜리 데이터 파일이 grep 에 걸릴 때마다 큰 출력이 오갔다** [실측] → `permissions.deny` 의 `Read(...)` 로 읽기 차단(overlay).
31. **읽기 차단 규칙이 자기 명령도 막았다** [실측] — 차단한 파일 이름이 인자로 섞인 셸 명령(`grep`·`sed`)까지 거부됐다.
    → 그 파일을 다뤄야 하면 경로를 직접 적지 않는 스크립트로. 차단 규칙을 넣은 직후 자주 쓰는 명령을 한 번 돌려 본다(L2-4).

## E. 플랫폼 제약

32. **클라우드 세션은 저장소의 플러그인·마켓플레이스를 설치하지 않는다** [문서] — 커밋된 CLAUDE.md · `.claude/{agents,skills,rules,commands}` ·
    훅만 로드된다. → 이 템플릿은 플러그인이 아니라 **파일을 소비자에 커밋**하고 lock 으로 고정한다.
33. **훅 설정은 세션 시작 때 한 번 스냅샷된다** [실측·문서] — 세션 중에 고쳐도 그 세션엔 적용되지 않는다. 그동안은 판단 지점마다 직접 실행.
    훅이 가리키던 옛 경로는 지우지 말고 위임 스크립트로 남긴다(이미 떠 있는 세션이 그 경로를 부른다).
34. **`disable-model-invocation: true` skill 은 서브에이전트에 미리 넣을 수 없다** [문서] — 지휘자 전용 문서에는 맞고, 작업 에이전트용 요약에는 안 맞다.
35. **경로 한정 규칙(`.claude/rules/*.md` + `paths:`)이 서브에이전트에서도 그 파일을 읽을 때 로드되는지는 문서에 명시가 없다** [미확인]
    → 불변식을 옮기기 전에 작은 서브에이전트로 실험한다. 확신이 없으면 CLAUDE.md 에 둔다.
36. **GITHUB_TOKEN 으로 만든 PR·푸시는 다른 워크플로를 깨우지 않는다** [일반] — 자동 동기화 PR 의 CI 가 안 돌 수 있다.
    워크플로 파일을 고치는 푸시는 별도 권한이 필요하다 → 동기화 대상(payload)에 워크플로를 넣지 않았다.
37. **사용량 판정의 「경량 QA」 는 속도 조절이지 품질을 낮추라는 뜻이 아니다** [실측 — 의사결정자 지적] · **완료 시점에도 한도를 본다**
    — 429 로 검증자 둘이 같은 순간에 죽어 한쪽 보고서를 잃었다.

## F. 배포·사용자에게 닿는 것

38. **업데이트 안내 문구를 게시 1분 뒤에 올렸더니 첫 안내 창이 기본 문구였다** [실측]
    앱이 읽는 원본 파일 주소가 CDN 에서 `max-age=300` 으로 캐시됐다. → 사용자에게 보이는 자료는 **게시 전에** 올리고(그 버전이 게시돼야만
    쓰이므로 미리 올려도 무해), 캐시를 거친 실제 주소로 확인.
39. **위험한 동작의 확인 단계가 더블클릭 한 번에 무력화됐다** [실측] — 확인 버튼이 원래 버튼 자리에 나타나 두 번째 클릭이 곧바로 확인.
    → 그 자리에는 「취소」, 런타임 검증은 같은 자리 연속 클릭으로도 두드린다. (적대적 검증자 정의)
40. **개발 모드에선 멀쩡한데 설치본에서만 모듈을 못 찾았다** [실측] — 패키징 파일 목록 누락. → 다른 플랫폼 타깃으로라도 패키징해 확인하거나 미확인으로(L2-6).
41. **자동 업데이트가 semver 비교만 해서, 기능이 많은 개발 줄 빌드가 유지보수 줄의 다음 판을 「업데이트」 로 받을 뻔했다** [실측 — 검증에서 잡음]
    → 개발 줄의 버전을 유지보수 줄의 어떤 판보다 크고 다음 주 버전보다 작게(예: `1.99.0`) 두고, 릴리즈 워크플로가 개발 줄에서 낮은 버전 게시를 거절.
42. **UI 만 막고 그 UI 가 부르는 통로는 열어 뒀다** [실측] — 금지된 순간에도 콘솔에서 함수를 직접 부르면 동작했다. → L2-1: 진입점은 통로까지 센다.
