# 에이전트 브리프 템플릿 (L3)

**오케스트레이터용.** 작업 에이전트를 띄울 때 이 파일을 복사해 채운다.
기억에 의존해 매번 새로 쓰면 빠뜨린다 — 실제로 빠뜨렸다.

세션은 사라지지만 이 파일은 남는다. 다음 세션의 지휘자가 읽는다.
에이전트 정의(`.claude/agents/ops-*.md`)를 쓰면 역할·도구 제한은 정의가 맡고, 브리프는 **이번 작업**만 적으면 된다.

## 오케스트레이터 체크리스트

브리프를 보내기 전에:

- [ ] **금지 항목마다 대체 경로를 적었는가**
      "X 하지 마라" 만 적으면 그 경로의 검증이 사라진다. 실제로 외부 결제 API
      호출을 금지했다가 런타임 검증자가 결제 경로를 아예 못 두드렸고,
      이중 청구 버그를 다른 검증자 한 명만 잡았다.

- [ ] **깨지면 안 되는 기존 보호 장치를 명시했는가**
      사고 사례와 함께 적는다. "왜 있는지" 를 모르면 지운다.

- [ ] **판단이 필요한 곳에 결론을 지시하지 않았는가**
      해법을 지시하면 더 나은 해법이 나올 자리가 없어진다.

- [ ] **작업 크기가 컨텍스트 약 25만 안에서 끝날 범위인가**
      큰 에이전트(최대 컨텍스트 40만 이상)가 전체 캐시 읽기의 절반을 썼다(실측). 넘을 것 같으면 쪼갠다.

- [ ] **「이미 확인한 위치」 를 넘겼는가**
      탐색 에이전트(싼 모델)가 만든 지도를 여러 구현자가 같이 쓰면 같은 탐색을 반복하지 않는다.

작업이 끝난 뒤:

- [ ] **보고서를 파일에서 읽었는가 — 요약부터**
      완료 알림의 결과 필드는 자주 비거나 잘린다. 보고서 디렉터리를 읽는다. 원문 전체는 필요한 절만.

- [ ] **끝난 큰 에이전트를 다시 깨우지 않았는가**
      5분 넘게 지났고 컨텍스트가 15만을 넘는 에이전트는 메시지로 다시 깨우지 않는다 — 캐시가 식어
      그 컨텍스트 전체를 다시 쓴다(실측: 다시 깨운 요청이 큰 캐시 쓰기의 상당 부분). 대신 보고서의 요약·
      「판단한 것」·검증 결과를 붙인 **새 브리프**로 수정 에이전트를 띄운다.

- [ ] **구현자와 다른 사람이 검증하는가**

- [ ] **검증자 둘의 접근이 서로 다른가**
      예: 코드를 읽고 공격 시나리오를 재현하는 쪽 / 실제로 띄워 HTTP 로 두드리는 쪽.
      접근이 같으면 둘 다 같은 것을 놓친다.

- [ ] **검증자가 "통과" 라고 한 치명·중대 항목을 직접 확인했는가**
      검증자도 틀린다. 검증자가 제안한 수정안이 계산해 보니
      문제를 못 막는(오히려 조금 나빠지는) 경우가 있었다.

- [ ] **다시 검증은 범위를 좁혔는가**
      작은 수정 뒤의 재검증은 바뀐 부분 + 이전 결함 재현으로. 처음 검증의 깊이는 줄이지 않는다.

- [ ] **머지 직전에 브랜치 기준점을 다시 확인했는가**
      작업이 길어지면 그 사이 기본 브랜치가 움직인다.

- [ ] **사용자 판단이 필요한 지점을 단정하지 않고 올렸는가**
      상품·법무·비용이 섞인 결정은 선택지와 각각의 결과로.
